- Centre of Gravity: 15mm aft of the centerline of the carbon rod front wing spar, ~25% MAC.
- Belly has two landing pads either side of the centreline; the airframe manufacturer's documentation designates the centreline location between them as the intended camera mount position (per Julian, 2026-07-06). ## Telemetry Rate Tuning - 2026-07-05

Investigated slow-updating telemetry (battery current/capacity, in particular) on both the DBR4/ELRS link (TELEM1) and the RFD900x link (TELEM2):
- ELRS packet rate set to 100Hz Full on the GX12/DBR4 pair.
- `mavlink status`/`mavlink status streams` (via QGC MAVLink Console) identified the two MAVLink instances: MAV_0 (TELEM2/RFD900x, device `/dev/ttyS4`, mode Normal) and MAV_1 (TELEM1/DBR4, device `/dev/ttyS6`, mode OSD).
- MAV_0 was bandwidth-starved (`MAV_0_RATE` found live at 1200 B/s, throttling every message to ~39% of its configured rate) despite `docs/engineering/ICD.md` already documenting 3000 B/s - the live parameter had reverted or been changed without the docs being updated. Reset to 3000 B/s to match.
- MAV_1 was not bandwidth-starved (only ~12% of its 9600 B/s budget in use) but `BATTERY_STATUS` was hard-set to 0.5Hz by the OSD mode default; raised `MAV_1_RATE` to 19200 B/s for headroom and overrode `BATTERY_STATUS` specifically.
- Per-message rate overrides added via `mavlink stream -d <device> -s BATTERY_STATUS -r <hz>`: 5Hz on MAV_0 (`/dev/ttyS4`), 10Hz on MAV_1 (`/dev/ttyS6`).
- To persist across reboots, these commands must go in `/fs/microsd/etc/extras.txt` (not the SD card root - PX4 does not source a root-level `extras.txt`). This FC's NuttX shell (console) cannot create new files via `echo >`/`echo >>` redirection - `mkdir` and `mv` work, and appending to an already-existing file with `>>` works, but creating a new file this way does not. The file had to be created on a PC after physically removing the SD card. Watch for missing newlines between appended lines when using `>>` from the console - it does not insert a separator, so lines run together and break parsing at boot.
- `SER_TEL1_BAUD` (DBR4 UART) was left at 460800 - not changed.

## Airframe Aerodynamic Characterisation - Weishäupl et al. 2024 - 2026-08-31

Julian provided an academic paper - Weishäupl, McLay & Sóbester, "Experimental evaluation of the drag curves of small fixed wing UAVs," *The Aeronautical Journal* 128 (2024), pp. 655-684 - now archived at `docs/engineering/references/weishaupl-et-al-2024-drag-curves-small-fixed-wing-uavs.pdf`. The paper's "FliTePlat" test platform is explicitly built on the MakeFlyEasy airframe (their reference [12], the same manufacturer as the Believer), and its Table 1 geometry matches the Believer's manufacturer specs closely: wingspan 1.96m (exact), length 1.07m (exact), fuselage height 0.18m (close), MTOW 5.5kg (exact), manufacturer cruise speed 20m/s (exact). Reference area is quoted as 0.488m² vs the Believer's documented 51dm² (0.51m²) - close but not identical, a ~4% difference not fully reconciled. This is very likely the same commercial airframe, or an extremely close sibling model.

**The paper does not name the motor manufacturer, model, or KV rating anywhere** - propulsion is only described generically as "two wing-mounted electric motors." Propeller used in their testing: 12" diameter, 6" pitch, 2 blades - differs from the Believer's current 11x7 Hobbyrama prop, so not directly transferable for prop-specific modelling (the drag polar coefficients below are airframe-level and prop-independent, however).

**Wind-tunnel-measured drag polar (their most reliable "clean" reference, Table 2):**

| Coefficient | Value |
|---|---|
| CD0 (zero-lift drag) | 0.0503 |
| K (induced drag constant) | 0.0764 |
| CL0 (zero-AoA lift coefficient) | 0.2570 |
| CLα (lift curve slope) | 0.1122 /deg |

Derived performance (their Table 3, wind tunnel reference): L/Dmax = 8.07, max range 114km, max endurance 157min.

**Other extracted facts:**
- Measured 1g stall airspeed: 11 m/s, well above the Believer's previous `FW_AIRSPD_STALL` = 7 m/s (an untuned PX4 generic default) - `FW_AIRSPD_STALL` set to this value and `FW_AIRSPD_MIN` raised accordingly under CTL-10, `docs/project/build-checklist.md`.
- Max dive airspeed (VNE, flutter-limited): 37 m/s.
- Load factor limits: 0.2 to 3.8g, mostly wing-deformation limited rather than structural failure.
- Confirms the same operational profile as the Believer: no conventional undercarriage, hand-launch or trolley-launch departure, belly-landing recovery, V-tail with ailerons and ruddervators.

**Open strategic question**: this is a real, wind-tunnel-measured whole-airframe drag polar, which is a stronger basis for performance estimation than modelling the wing alone against the generic Eppler 374 stand-in currently used for PROP-05 (`docs/project/build-checklist.md`). Not yet decided whether to use these coefficients directly (e.g. via the Brequet range/endurance equations the paper itself uses) instead of, or alongside, the MotoCalc/E374 approach.

## Control Allocation and Control-Surface Configuration Review - 2026-08-31

Julian conducted a flight-control configuration review in a separate session and supplied a detailed summary brief for this repository to be updated from. This entry supersedes the *interpretation* of the 2026-07-10 TMAC and 2026-08-19 settings recorded above as still-current baseline decisions - those entries remain accurate historical records of what was done and why at the time, and are not rewritten.

**Core finding**: the PX4 Actuators page's Roll/Pitch/Yaw Torque fields (`CA_SV_CSx_TRQ_*`) are actuator-effectiveness coefficients used by the control allocator - normalized estimates of how effective an actuator is about a given axis, inserted into an allocation matrix and inverted to calculate actuator commands. They are **not** conventional transmitter mixer percentages and are not a direct command for a percentage of servo travel; increasing a coefficient can *reduce* the requested deflection for a given demanded moment, because PX4 is being told the actuator is more effective. This reframes several decisions made on 2026-08-19 under that mistaken assumption:

- The V-tail yaw-effectiveness values set to ±0.85 on 2026-08-19 were understood then as "raising the rudder mixing gain"/an "85% rudder mix." They are now understood to instead tell PX4 each V-tail surface is 1.7x as effective in yaw as in pitch (pitch coefficient stayed at 0.50) - a ratio with no aerodynamic derivation or flight-test evidence behind it. **Target: restore to the PX4 type-default ±0.50** (full baseline: Left Aileron Roll -0.50/Pitch 0/Yaw 0; Right Aileron Roll +0.50/Pitch 0/Yaw 0; Left V-Tail Roll 0/Pitch +0.50/Yaw +0.50; Right V-Tail Roll 0/Pitch +0.50/Yaw -0.50) - tracked as `docs/project/build-checklist.md` CTL-06. The aileron mixer trims (-0.08/-0.03) are unaffected and are to be retained through this reset - Julian has confirmed they are correctly established.
- **Endpoint-based aileron differential is no longer accepted as the project's validated baseline.** The asymmetric PWM ranges set 2026-08-19 (informed by the QGroundControl Actuators Config screenshot) may produce some asymmetric physical travel, but this was never a deliberate, reversible, quantified differential law - it conflated actuator safety endpoints (which legitimately vary per-servo due to installation differences) with aerodynamic mixing. The installed PX4 1.16.1 control-allocation interface exposes one linear coefficient per surface and no conventional aileron-differential parameter - a finding specific to this PX4 version, not a permanent limitation of all future releases. **Decision: no software aileron differential in the baseline configuration**; only reconsider if flight testing shows significant adverse yaw or another handling problem it would help. PWM endpoints are to be independently remeasured as genuine safe mechanical limits per servo (CTL-06) - the final values are presently TBD and must not be assumed symmetric.
- **No aileron-to-rudder mix is being added.** `FW_RLL_TO_YAW_FF` (roll-to-yaw feedforward, currently 0.0) remains 0.0 in the baseline; it is a controller feedforward term, not a percentage-mixer equivalent, and PX4 Stabilized mode already performs a coordinated turn on a non-zero roll stick. Additional feedforward will only be tuned upward, in small documented increments, if flight testing demonstrates meaningful adverse yaw - tracked as `docs/project/build-checklist.md` CTL-07 (deferred until CTL-06/CTL-08 complete).
- **The three `FW_MAN_*_SC` parameters remain unchanged at 1.0.** The observed bench behaviour (ailerons reaching max deflection at ~±50% stick, while the QGroundControl Radio page correctly reports the full ~-100%/+100% gimbal range) narrows away a gross RC-calibration error but does not confirm `FW_MAN_R_SC` is the cause - `FW_MAN_*_SC` only scale commands in full Manual mode, whereas Acro (rate) and Stabilized (attitude) modes can legitimately saturate a surface on a stationary bench well before full stick, since the aircraft can't respond to the commanded rate/attitude. A value near 0.5 for `FW_MAN_R_SC` is a provisional test hypothesis only, not an approved setting - it must be reproduced and confirmed in full Manual mode, after CTL-06 establishes a correct actuator baseline, before being written in as a new setting. Tracked as `docs/project/build-checklist.md` CTL-08.
- **V-tail bench saturation under full combined pitch+yaw is expected, not necessarily a mixing fault.** With the default matrix, ruddervator commands are roughly proportional to P+Y and P-Y; a surface already at its pitch limit will appear to stop as yaw is added while the other surface moves back toward neutral. Acceptance testing (CTL-06) should check correct direction, distinct response at moderate combined inputs, no binding, and safe endpoints - not that both surfaces keep moving independently at the extreme corner of the command envelope.

PWR-03 (servo rail load test) now also depends on CTL-06, since load test results against superseded endpoints wouldn't represent the final configuration. None of CTL-06/07/08 were promoted or demoted in priority by this review (CTL-06/08 remain Urgent, CTL-07 remains Non-critical) - this review did not make a governance decision to change task priority classification, only to correct their scope and dependencies.

**Files deliberately not yet updated**: `docs/engineering/ICD.md`, `docs/operations/Pixhawk Parameter Backup/parameter-change-log.md`, and the `.params` backup still describe the as-found state (±0.85, current endpoints, all three `FW_MAN_*_SC` at 1.0) and must not be replaced with target values until the physical configuration has actually been changed, tested, and re-exported from the live flight controller. `docs/operations/manual.md`'s Manual-mode pre-flight check wording is to be refined after CTL-08 concludes, not now.
